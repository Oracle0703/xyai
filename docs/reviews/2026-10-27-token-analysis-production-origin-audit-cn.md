# Token Analysis 来源判断生产审计（2026-10-27）

## 结论

存在机器请求被标成“人工”的情况。对固定 24 小时内全部 **3,591 条人工标签**核对元数据和末尾输入结构，检出 **87 条显式机器任务**及 **391 条高置信客户端机器形态**，合计 **478 条**。对应人工标签中的检出比例为 **13.31%**，占同期 **60,065 条已归档已索引请求的 0.80%**。

这是按请求用途及客户端协议结构判断的保守检出比例，不是独立人工操作日志验证的完整误判率。最严格的显式元数据口径为 **87 / 3,591 = 2.42%**（占全部归档请求 **0.145%**）。其余未证实记录不能算作全部正确。对 AI 标签分层抽查 **470 条**，未发现可确认的新人工输入误标 AI；不能把 0/470 外推为全量 AI 零误判或系统准确率 100%。

本轮只读生产数据库与归档，不改变生产代码、数据、配置、索引或服务。仓库已有 Claude 的风险分类数据层修改保持原样，本报告审计的是生产部署版本。

- AI 470 条中观察到：末有效事件为工具结果 443、代理消息 18、Guardian 专用审查 7、子代理委派 1、assistant 后 reminder-only 续执行 1；未发现可确认的新用户输入误标 AI。
- 不能拿旧人工输入预览证明当前工具续执行应为人工，也不能拿分类器回放与入库一致证明分类准确。本轮判断基于原始请求结构和独立复核。

## 后续修复建议（未执行）

1. 先补明确的新 trigger；标题采用 `thread_source=thread_title` 加专用任务形态，避免泛化所有来源枚举。
2. 固定压缩按完整模板匹配，仅正规化换行与首尾空白；纯通知/技能/系统更新包装要求完整闭合、结构合法、包装外无新正文，并结合之前的有效事件。用户引用标签、未闭合标签、包装后有新问题必须保留人工判断。
3. 专用辅助任务识别结合系统用途与当前输入；不要按“摘要/标题/JSON/Python/User-Agent”等关键词或调用工具数量归类。普通程序 API 调用如果没有来源证据，继续明确展示推断边界。
4. 用本包做回归，既验证检出的机器请求，也验证 question-reply、恢复摘要后新问题、包装后新正文等防误伤场景。修改分类规则后需要版本化和受控历史补判；本轮没有重索引或回填。
