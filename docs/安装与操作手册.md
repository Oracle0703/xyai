# Sub2API 一键安装与操作手册（Ubuntu 20.04）

> **适用范围：仅限历史安装包 `sub2api-main-b3ff5895-ubuntu20.04-installer-20260527-005842.zip`，不是现行安装手册。**
>
> 安装包来源：2026-05-27 在本机由 `main@b3ff58955c7e10b44148e742230174dba9fdda72`（2026-05-26）打包，产物位于被 Git 忽略的 `release/` 目录，未随仓库发布。配套脚本 `install-source-ubuntu20.04.sh` 只存在于该安装包内，从未提交到仓库，当前仓库没有 `deploy/install-source-ubuntu20.04.sh`。
>
> 文中依赖版本只对应该安装包（例如 Go 1.26.3）；当前源码要求 Go 1.27.0（`backend/go.mod`），不能用本手册安装当前版本。现行部署方式请阅读 `README_CN.md`、`deploy/README.md`、`LOCAL_STARTUP_NOTES.md`。

## 1. 安装包内容

发布时将脚本和源码放在同一个外层 zip 安装包中，例如：

```text
sub2api-main-b3ff5895-ubuntu20.04-installer-20260527-005842.zip
```

解压后目录结构：

```text
sub2api-main-b3ff5895-20260526-234815/
  install-source-ubuntu20.04.sh
  sub2api-main-b3ff5895.zip
  README-安装.txt
```

| 文件 | 说明 |
| --- | --- |
| `install-source-ubuntu20.04.sh` | Ubuntu 20.04 一键安装脚本 |
| `sub2api-main-b3ff5895.zip` | main 分支生产源码包 |
| `README-安装.txt` | 安装包内简明说明 |

## 2. 脚本做什么

| 步骤 | 内容 |
| ---: | --- |
| 1 | 检查 root 权限、系统版本和 CPU 架构 |
| 2 | 生成默认密钥和密码 |
| 3 | 配置 Ubuntu 国内 apt 源 |
| 4 | 自动禁用会影响安装的历史第三方 apt 源，并安装基础工具包 |
| 5 | 配置 PostgreSQL 15、Redis 7、Node.js 20 软件源 |
| 6 | 安装 PostgreSQL 15、Redis 7、Node.js 20 |
| 7 | 安装 Go 1.26.3 |
| 8 | 配置 npm/pnpm 国内源 |
| 9 | 自动发现并解压同目录的生产源码 zip 包 |
| 10 | 创建数据库、运行用户、数据目录 |
| 11 | 构建前端和后端 |
| 12 | 写入环境变量文件 |
| 13 | 创建并启动 systemd 服务 |
| 14 | 打印访问地址、默认账号和数据库/Redis 密码 |

脚本包含详细中文注释和步骤进度打印，执行时会显示 `步骤 x/14`。

## 3. 快速安装

将外层安装包上传到 Ubuntu 20.04 服务器，例如上传到 `/root`：

```text
/root/sub2api-main-b3ff5895-ubuntu20.04-installer-20260527-005842.zip
```

解压：

```bash
mkdir -p /root/sub2api-install
unzip /root/sub2api-main-b3ff5895-ubuntu20.04-installer-*.zip -d /root/sub2api-install
```

进入解压目录并执行：

```bash
cd /root/sub2api-install/sub2api-main-b3ff5895-20260526-234815
sudo SOURCE_ZIP=$(pwd)/sub2api-main-b3ff5895.zip bash install-source-ubuntu20.04.sh
```

安装完成后，脚本会在终端展示：

| 信息 | 说明 |
| --- | --- |
| 前端访问 URL | 管理后台和用户页面访问地址 |
| 后端 API URL | API 客户端配置的 Base URL |
| 默认管理员邮箱 | 初始登录账号 |
| 默认管理员密码 | 初始登录密码 |
| 数据库名/用户名/密码 | 供管理员保存 |
| Redis 地址/密码 | 供管理员保存 |
| 环境变量文件 | 默认 `/var/lib/sub2api/sub2api.env` |

默认访问：

```text
http://服务器IP:8080
```

健康检查：

```bash
curl http://127.0.0.1:8080/health
```

## 4. 可选配置

脚本支持通过环境变量自定义安装参数：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `INSTALL_DIR` | `/opt/sub2api` | 项目安装目录 |
| `DATA_DIR` | `/var/lib/sub2api` | 数据、日志、环境变量目录 |
| `SERVICE_USER` | `sub2api` | 运行服务的系统用户 |
| `SERVER_PORT` | `8080` | 后端监听端口 |
| `DB_NAME` | `sub2api` | PostgreSQL 数据库名，可自定义 |
| `DB_USER` | `sub2api` | PostgreSQL 用户名，可自定义 |
| `DB_PASSWORD` | 自动生成 | 数据库密码 |
| `ADMIN_EMAIL` | `admin@sub2api.local` | 初始管理员邮箱 |
| `ADMIN_PASSWORD` | 自动生成 | 初始管理员密码 |
| `USE_NPM` | `false` | 设置为 `true` 时用 npm 构建前端 |
| `SOURCE_ZIP` | 自动发现 | 生产源码 zip 包路径；多个 zip 时必须指定 |
| `GIT_REPO` | 官方仓库地址 | 没有 zip 且非源码目录时兜底克隆的仓库 |
| `GIT_BRANCH` | `main` | 兜底克隆分支 |

示例：

```bash
sudo DB_USER=my_sub2api_user \
  DB_NAME=my_sub2api_db \
  SERVER_PORT=8080 \
  ADMIN_EMAIL=admin@example.com \
  SOURCE_ZIP=/root/sub2api-install/sub2api-main-b3ff5895-20260526-234815/sub2api-main-b3ff5895.zip \
  bash install-source-ubuntu20.04.sh
```

说明：`DB_USER` 和 `DB_NAME` 只能使用字母、数字、下划线，且不能以数字开头。

## 5. 国内源说明

脚本默认尽量使用国内源降低安装失败概率：

| 类型 | 默认源 |
| --- | --- |
| Ubuntu apt | 清华 Ubuntu 源 |
| PostgreSQL apt | PostgreSQL 官方历史归档源 `https://apt-archive.postgresql.org/pub/repos/apt/` |
| Redis apt | Redis 官方 apt 源 |
| Node.js apt | NodeSource Node.js 20 源 |
| npm/pnpm | `https://registry.npmmirror.com` |
| Go module | `https://goproxy.cn,direct` |
| Go 下载 | `https://golang.google.cn/dl` |

如需覆盖：

```bash
sudo APT_MIRROR=https://mirrors.aliyun.com/ubuntu/ \
  NPM_REGISTRY=https://registry.npmmirror.com \
  bash install-source-ubuntu20.04.sh
```

脚本会在 `apt-get update` 前自动检查并临时禁用会影响本次安装的历史第三方 apt 源，目前包含 Docker 官方源和旧的清华 PostgreSQL PGDG 源；被调整文件会备份到 `/root/sub2api-apt-source-backup/`。

## 7. 初始化流程

| 顺序 | 操作 |
| ---: | --- |
| 1 | 登录管理员账号 |
| 2 | 进入“系统设置”，配置站点、注册、支付、OAuth 等 |
| 3 | 进入“分组管理”，创建服务分组 |
| 4 | 做账号评估，按用户规模估算上游账号数量 |
| 5 | 进入“账号管理”，添加上游账号或 API Key，并绑定分组 |
| 6 | 进入“用户管理”，创建用户、分配余额或订阅 |
| 7 | 用户进入“API Keys”，创建并复制 API Key |
| 8 | 用生成的 API Key 调用网关接口 |

账号评估建议：

| 项目 | 建议 |
| --- | --- |
| 单用户并发 | 每人最大建议 `3` 个并发 |
| 账号数估算 | `人数 × 每人并发 ÷ 10`，保守可用 `人数 × 每人并发 ÷ 12` |
| 示例 | 100 人、每人 3 并发，建议准备约 `25-30` 个上游账号 |

## 9. API 调用示例

OpenAI Chat Completions：

```bash
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer sk-your-sub2api-key" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"你好"}]}'
```

Anthropic Messages：

```bash
curl http://127.0.0.1:8080/v1/messages \
  -H "Authorization: Bearer sk-your-sub2api-key" \
  -H "Content-Type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -d '{"model":"claude-sonnet-4-5","max_tokens":256,"messages":[{"role":"user","content":"你好"}]}'
```

常用端点：

| 类型 | 端点 |
| --- | --- |
| Anthropic | `/v1/messages` |
| OpenAI Responses | `/v1/responses` |
| OpenAI Chat | `/v1/chat/completions` |
| OpenAI 图片 | `/v1/images/generations`、`/v1/images/edits` |
| Gemini | `/v1beta/models/{model}:generateContent` |
| Antigravity | `/antigravity/v1/messages` |

## 10. 升级

如果脚本通过 `GIT_REPO` 克隆安装，进入安装目录后重新拉取、构建并重启：

```bash
cd /opt/sub2api
sudo git pull
sudo corepack prepare pnpm@10.23.0 --activate
sudo pnpm --dir frontend install
sudo pnpm --dir frontend run build
cd backend
sudo /usr/local/go/bin/go mod download
sudo make build
sudo systemctl restart sub2api
```

如果脚本是在已有源码目录中执行，安装目录是源码副本；升级时建议在原源码目录拉取新代码后重新执行安装脚本，或手动把新源码同步到 `/opt/sub2api` 后再执行构建命令。

使用 npm 时，将前端两行替换为：

```bash
sudo npm --prefix frontend install
sudo npm --prefix frontend run build
```

升级前建议备份 PostgreSQL 和 `/var/lib/sub2api`。

## 11. 常见问题

| 现象 | 处理 |
| --- | --- |
| 脚本提示不是 Ubuntu 20.04 | 本脚本只适配 Ubuntu 20.04，请更换系统或手动安装 |
| PostgreSQL/Redis 安装失败 | 检查服务器是否能访问脚本中配置的软件源 |
| Go 下载失败 | 可设置 `GO_DOWNLOAD_HOST` 为可访问的 Go 下载镜像 |
| 前端依赖安装失败 | 检查 npm registry，或设置 `USE_NPM=true` 改用 npm |
| 页面打不开 | 检查 `systemctl status sub2api`、端口和防火墙 |
| API 返回 401 | 检查 `Authorization: Bearer sk-...` |
| API 返回 403 | 检查余额、订阅、分组权限、Key 是否绑定分组 |
| 上游失败 | 在账号管理中测试账号和代理，查看运维监控错误日志 |

Nginx 反代给 Codex CLI 等客户端使用时，在 `http` 块加入：

```nginx
underscores_in_headers on;
```

不同客户端引用上下文和添加图片的差异：

| 客户端 | 引用上下文 | 添加图片 |
| --- | --- | --- |
| Codex CLI | 主要基于当前工作目录、命令输出和手动说明；需要明确写文件路径或粘贴相关内容 | 可在提示中给出本地图片路径，或说明图片位置；是否可直接识别取决于当前 CLI/模型能力 |
| Codex for VS Code | 更适合引用当前工作区、打开的文件、选中代码和编辑器上下文 | 通常以 VS Code/扩展提供的附件或路径能力为准；不确定时使用图片文件路径说明 |
| Codex App | 可结合当前工作区文件、终端输出、截图/图片附件和本地路径 | 支持通过会话附件或本地绝对路径引用图片，适合做界面截图、设计稿、报错截图分析 |
| GitHub Copilot | 在 IDE 中常用 `#file`、`#selection`、`#codebase` 等方式引用上下文，具体能力取决于 Copilot Chat 与 IDE | 支持在聊天中附加图片或截图的环境可直接使用；不支持时需用文字描述或提供文件路径 |

如果想使用集成度更高的 IDE，可在 Trae 中配置 Sub2API 中转地址和 API Key 使用，获得更完整的一体化 IDE 体验。
