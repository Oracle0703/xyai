# 迅游 AI 公司介绍页

面向公司管理层与各部门同事，建议讲解 8–10 分钟。主文件为 [index.html](index.html)，所有样式、脚本和图形都内嵌在单个 HTML 中，可离线打开、复制分享。

## 打开与使用

| 方式 | 操作 |
| --- | --- |
| 离线阅读 | 用 Chrome 或 Edge 打开 `index.html`；无需安装依赖 |
| 本地预览 | 在仓库根目录执行 `python -m http.server 8769 --bind 127.0.0.1 --directory docs/delivery/2026-10-29-company-introduction`，访问 `http://127.0.0.1:8769/` |
| 现场讲解 | 点击右上角「演示模式」；底部按钮或左右方向键切换章节，Esc 退出；长章节仍可滚动 |
| 岗位演示 | 选择岗位，点击「播放场景演示」，查看预设任务及产出；可复制任务模板 |
| 协作演示 | 点击流程节点或播放整条协作链，查看上下游交付物 |
| 价值测算 | 修改人数、任务频次、前后耗时、有效利用比例、工时价值与月度投入 |
| 静态留档 | 页脚「打印 / 保存 PDF」使用浏览器打印；打印保留当前选择的岗位与测算参数 |
| 减少动效 | 页脚切换动效；也尊重操作系统的减少动态效果设置 |

此页没有调用业务 API、模型服务或外部 CDN，场景演示是明确标注的预设内容。复制权限不可用时会选中文本供手动复制。没有配置生产站点链接或提交表单；试点申请按钮只复制模板。

## 建议讲解路线

| 章节 | 建议时间 | 讲解重点与操作 |
| --- | --- | --- |
| 项目介绍 | 45 秒 | “我们建设的是公司统一 AI 接入与管理服务，让模型能力进入大家日常使用的工具。” |
| 建设意义 | 60 秒 | 员工减少重复接入，团队复用方法，公司看清资源投入。说明开源底座与公司适配、运维的贡献。 |
| 使用基础 | 45 秒 | 135 个启用账号、111 个近 30 天使用账号、约 105 万条记录调用，均为 2026-10-23 快照。证明持续使用基础，暂不把调用数换算为业务收益。 |
| 岗位场景 | 2 分钟 | 推荐各演示一次“研发工程师”和“市场与运营”，体现技术与非技术岗位；按参会者切换其他岗位。强调输入约束、可用成果、人工复核。 |
| 跨岗协作 | 60 秒 | 播放会员权益页改版链路。每一步都有下一岗接得住的成果，输出在现有团队工具中流转。 |
| 管理价值 | 60 秒 | 统一模型入口、额度与费用、按职责授权、持续维护。部门能力是可配置能力，历史快照不证明已完成部门推广。 |
| 价值测算 | 90 秒 | 默认示例：40 人、每周 3 次、50 分钟降到 30 分钟（含复核），月释放约 173.2 小时；60% 有效利用、100 元/小时、6,000 元总投入，折算净值约 4,392 元/月。这是示例产能估算，不能当作已实现节约。 |
| 推广建议 | 60 秒 | 每个试点部门 1 位共建人、2 类高频任务，四周收集真实样本；由使用方确认效果后决定推广。 |

建议开场：

> 今天想介绍的是，我们怎样让 AI 从个人尝试，变成公司各岗位更容易使用、团队更容易协作、投入更容易管理的一项能力。迅游 AI 中转站已经有持续使用基础，我们希望把这个基础延伸到更多真实工作任务。

建议结尾：

> 我们希望每个愿意参与的部门带来两类高频任务，指定一位共建人。用四周把接入、试用、复核和效果记录走通，让下一次推荐建立在真实案例与业务确认之上。

## 测算规则

- 月释放工时 = 参与人数 × 每周任务数 × 4.33 ×（原耗时 − AI 后耗时）÷ 60。
- 有效产能折算价值 = 月释放工时 × 有效利用比例 × 工时价值。
- 产能折算净值 = 有效产能折算价值 − 月度总投入。
- 月度总投入建议包含模型 / 订阅、服务器、维护支持、培训及建设成本月度分摊。
- 输入允许 AI 后耗时更长、零有效利用、零参考工时价值与零成本；负向结果不会被隐藏。
- 4.33 是每月周数的估算系数。参与人数与顶部平台账号数没有计算绑定。
