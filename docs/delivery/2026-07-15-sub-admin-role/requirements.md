# 子管理员角色需求

## 目标

在不改变管理员和普通用户现有行为的前提下，新增账号级 `sub_admin` 角色。管理员可授权子管理员查看订阅管理、使用记录、Token 分析中的任意组合；子管理员只能调用对应只读接口，订阅管理额外允许重置配额。

## 使用者

| 使用者 | 需求 |
| --- | --- |
| 管理员 | 创建或编辑子管理员，并配置其管理菜单权限 |
| 子管理员 | 保留普通用户能力，并访问获授权的管理页面 |
| 普通用户 | 行为保持不变，不显示管理菜单 |

## 成功标准

| 编号 | 可验收结果 |
| --- | --- |
| AC-1 | 管理员始终可见并访问全部管理菜单和管理接口 |
| AC-2 | 子管理员只显示并访问账号已授权的管理菜单，直链和手工接口调用同样受限 |
| AC-3 | `admin.subscriptions` 允许查看订阅并执行两类配额重置，拒绝其他订阅写操作 |
| AC-4 | `admin.usage` 提供完整只读使用记录、统计、排行、错误详情和导出体验，不开放清理 |
| AC-5 | `admin.token_analysis` 提供只读统计、项目、请求、输入和索引状态，不开放立即索引 |
| AC-6 | 普通用户行为不变，所有管理接口均拒绝 |
| AC-7 | 权限撤销在下一次请求立即生效，未知权限码返回 400 |
| AC-8 | 数据迁移、角色、权限、鉴权、审计和前端权限行为有自动化验证 |

## 范围内

- `users.admin_permissions` JSONB 字段、Ent 模型、迁移与 DTO 映射。
- `admin`、`sub_admin`、`user` 三角色契约。
- 三个权限码及其菜单目录、后端 HTTP 方法和 Gin 路由模板白名单。
- 管理用户创建、编辑、筛选、角色徽章和权限配置。
- Auth store、路由守卫、侧边栏和三个授权页面的操作收口。
- 专用 403 处理、权限刷新和安全跳转。
- `llm-wiki` 与相关组件文档。

## 范围外

- 子管理员管理账号、风控、请求拦截、系统设置、权限配置或自定义菜单。
- 子管理员执行使用记录清理、Token 立即索引、订阅分配、延期、撤销、恢复或删除。
- 角色组、组织级 RBAC、资源级权限或自定义权限码。

## 约束

| 类型 | 约束 |
| --- | --- |
| 分支 | `feature/hy/10156_新增子管理员角色`，从本地 `main` 创建 |
| 迁移 | 新建 `backend/migrations/177_add_sub_admin_permissions.sql`，不改历史迁移 |
| 安全 | 后端数据库最新用户数据为准；白名单外默认拒绝；不能按 GET 泛化放行 |
| 兼容 | 管理员与 Admin API Key 全量绕过；普通用户行为不变 |
| 流程 | 按 TDD 执行，先记录失败测试，再写最小实现和回归验证 |

## 假设

- 标准模式下子管理员保留全部普通用户菜单并默认进入 `/dashboard`。
- backend 模式下子管理员至少需要一个管理权限，进入第一个授权页面。
- 子管理员可完成管理端合规确认，但合规接口本身不代表任何业务管理权限。

## 开放问题

无。用户已批准规格和计划。
