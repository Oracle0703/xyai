# Token Analysis 故障恢复与回归测试方案

状态：2026-11-02 故障后的修复设计，尚未修改/部署在线 writer、索引器或 UI。事故恢复脚本与验收见 `docs/delivery/2026-11-02-token-analysis-repair/`。

## 已确认的两个断点

1. `server/middleware/request_archive.go` 的 `writeRecord` 在 `os.File.Write` 部分成功后失败，只返回错误；后台循环继续向同一文件追加。磁盘满可留下不带换行的半条 JSON，再与后续完整记录粘连。仅修数据库重试不能解决此问题。
2. `service/token_analysis_indexer.go` 对解析错误和数据库错误统一推进 offset；水位写入错误被忽略。SQL 恢复后已跨过的行不会重试。摘要与用户输入分步写入，还可能出现摘要存在而输入缺失。自动索引只覆盖昨天、今天，单纯“遇错停止”仍不能保证跨两天的故障恢复。

## 建议实现顺序

| 优先级 | 修改 | 验收合同 |
| --- | --- | --- |
| P1 | 归档写入处理短写/ENOSPC | 记录写前偏移并校验写入字节数；单 writer 独占且确认安全时回退未完成尾部，否则隔离当前文件/段并停止向坏尾追加。重启恢复也检查尾部。保持网关请求不被归档故障阻塞，有界丢弃必须计数告警。多进程共享同一文件前先引入写入排他机制。 |
| P1 | 区分不可解析内容与可重试基础设施错误 | SQL、连接、超时、水位保存失败停止本轮；可靠 checkpoint 不越过未持久化行。内容错误可进入隔离清单后继续，不能无证据清除。 |
| P1 | 持久化恢复任务 | 按源文件身份 + 字节区间 + 行哈希登记唯一任务，记录首次/最近错误时间、错误类型、尝试次数、退避时间、处理状态。故障文件队列独立于昨天/今天日期窗口，停机重启后继续。DB 完全不可用时也须保留旧 checkpoint，不能依赖成功写入错误表才保证重试。 |
| P1 | 幂等与并发 | 同文件自动/手动/补录共用跨进程锁和 checkpoint CAS。请求摘要、用户输入及完成 checkpoint 尽量同事务；至少明确部分写入恢复协议。重试已有摘要须排除自身的重复请求计数，不重置质量评分/计费关联，不重复累计 processed/failed。 |
| P2 | 管理端受控补录入口 | 预检→候选数与不可恢复数→执行→逐项验证。校验原文哈希与身份，保留原始 byte offset；只补缺失事实，遇冲突停止。恢复请求/响应/输入分开计数，单次作业可取消并续跑。 |
| P2 | 状态展示 | 分离当前执行失败、历史失败、已恢复和不可恢复；标明最近 50 文件统计口径。不得把 response 错误数加进请求行总数。不要因为读取水位到 EOF 就宣称所有内容完整入库。 |
| P2 | 容量管理 | 归档、PG、WAL 共盘时设置容量阈值与告警；制定可配置保留期。存在未解决故障的文件不自动清理。不要将减少数据库暂存表大小当作根治归档占盘。 |

## 回归测试矩阵

| 场景 | 必须证明的结果 |
| --- | --- |
| Write 返回 n<len 且 ENOSPC；空间恢复再写下一条 | 不产生两条粘连；故障记录有可观测结果；后续完整记录仍可索引 |
| 短写无 error、尾部回退失败、重启遇坏尾、多 writer | 不静默接受短写；无法安全修尾时隔离；不截掉其他 writer 的有效数据 |
| 摘要 INSERT/用户输入 UPSERT/响应暂存失败 | 水位停在可恢复位置；恢复后摘要、输入、响应均齐全 |
| 初始/逐行/最终 checkpoint 写入失败 | 错误上报；不继续推进可靠水位；重放不增加唯一成功数 |
| 提交成功但客户端未收到确认、进程中断后重试 | 重放后内容与计数一致，质量评分和计费关联不受破坏 |
| 故障持续超过两天、跨日请求响应乱序 | 历史任务自动重试；响应暂存按 archive_id 合并，不错配账单 |
| 非法 JSON、坏请求体、不完整 EOF、截断 body | 按对应规则隔离/等待/降级；不能将基础设施错误当作永久坏数据跳过 |
| 原文件被改动、截断、移动；相同日期新文件 | 哈希/文件身份不符拒绝重放，不拿另一行冒充原文 |
| 自动、手动、补录并发以及锁租约变化 | 同一行不会被重复推进/记账；陈旧结果不能覆盖新水位和完成事实 |
| 用户仅打开今天页面但存在旧失败 | UI 明确历史来源；修复后能显示恢复数量和残留原因 |

隔离测试应包含真实 PostgreSQL 事务与断连/超时注入；ENOSPC/短写优先使用可注入文件接口，额外在隔离小文件系统做一次验证，禁止通过填满生产磁盘验证。线上补录只验证分析数据，不重发上游请求、不重做计费。
