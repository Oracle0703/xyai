# 订阅管理每日剩余额度排序与批量重置设计

## 目标

在管理端订阅列表增加迅游/速宝组织筛选，将整个筛选结果按每日额度剩余比例从少到多稳定排序，并允许管理员或具有订阅管理权限的子管理员一键重置当前筛选结果中全部生效订阅的日限。

## 用户界面

| 区域 | 设计 |
| --- | --- |
| 组织筛选 | 在现有状态、分组和平台筛选旁增加“全部组织 / 迅游 / 速宝”选项。请求值保持为空、`xunyou`、`wsdashi`。 |
| 排序 | 所有列表请求固定以每日额度剩余比例升序为主排序；表格现有排序字段和方向只作为比例相同记录的次排序，默认仍为 `created_at desc`。 |
| 无限额订阅 | 没有有效每日限额的订阅排在所有有限额订阅之后，再按现有排序规则排列。 |
| 批量操作 | 在“分配订阅”按钮之后增加“一键重置日限”按钮。没有分配权限的订阅子管理员仍显示该按钮。 |
| 确认与状态 | 点击后弹出二次确认；确认期间禁用按钮并显示进行中状态，防止重复提交。成功提示实际重置数量，零匹配时明确提示没有可重置订阅，失败时保留筛选并显示错误。 |

## 组织筛选合同

组织归属复用组织用量报表的业务口径，但不把展示名称写入 API 或数据库：

| 邮箱域名 | API 值 | 展示值 |
| --- | --- | --- |
| 精确等于 `xunyou.com`，忽略大小写 | `xunyou` | 迅游 |
| 精确等于 `wsdashi.com`，忽略大小写 | `wsdashi` | 速宝 |

匹配只检查 `@` 后的完整域名，不把 `team.xunyou.com` 等子域名归入迅游或速宝。订阅查询通过关联用户邮箱应用该条件。后端拒绝未知的非空组织值，不能静默回退为全部组织。

## 剩余比例与稳定排序

有限额订阅的每日剩余比例定义为：

```text
max(日限额 - 当前有效日用量, 0) / 日限额
```

“当前有效日用量”必须与列表已有展示归一化保持一致：普通订阅的日窗口已经跨过下一个日历日边界时按 0 计算；未过期的一次性日额度订阅继续使用已存储日用量。日限额为空、为 0 或小于 0 时视为无限额，不参与比例计算并排到有限额订阅之后。

最终顺序固定为：

1. 有有效日限额的订阅优先；
2. 每日剩余比例升序；
3. 比例相同时使用现有 `sort_by` 和 `sort_order`；
4. 仍相同时按订阅 ID 稳定排序。

排序必须在数据库分页之前完成，不能只对当前页做前端排序。列表 API 继续接受 `sort_by` 和 `sort_order`，其含义收窄为每日剩余比例相同记录的次排序，因此现有表头排序交互和默认 `created_at desc` 可以保留。

## 后端接口与数据流

### 列表接口

`GET /api/v1/admin/subscriptions` 增加可选查询参数 `organization=xunyou|wsdashi`。状态、用户、分组、平台和组织条件在同一个服务端查询中应用，随后执行每日剩余比例主排序和分页。

### 批量重置接口

新增 `POST /api/v1/admin/subscriptions/reset-daily-filtered`。请求体只接收当前已应用筛选的值：

```json
{
  "status": "active",
  "user_id": 123,
  "group_id": 456,
  "platform": "openai",
  "organization": "xunyou"
}
```

所有字段均可省略；省略表示该维度不过滤。页码、页大小和排序不进入请求体。无论传入何种状态，批量写入只处理执行时仍为 `active`、未删除且未过期的订阅，避免重置历史、撤销或已过期记录。

前端在打开确认框时复制最后已应用的筛选值，确认时提交该快照。用户在确认框打开后继续改变页面控件，不得改变本次待执行范围。

仓储层使用一次数据库批量更新清零 `daily_usage_usd`，并把 `daily_window_start` 写为配置时区当天 0 点；周、月用量及窗口不变。接口返回：

```json
{
  "reset_count": 12
}
```

数据库写入应是单次原子操作，不返回逐条部分成功。写入成功后，服务层针对受影响的用户/分组键失效进程内订阅缓存、共享计费缓存并发布跨实例失效通知。缓存失效错误记录日志，但不能把已经提交的数据库写入伪装成未执行。

该写接口支持项目现有 `Idempotency-Key` 机制，重复提交同一个键返回第一次结果，避免网络重试造成重复操作和误导性计数。

## 权限与错误处理

- 完整管理员可以读取组织筛选后的列表并执行批量重置。
- `admin.subscriptions` 子管理员权限继续允许单条重置，并新增允许批量重置路由；分配、调整、撤销和恢复权限不扩大。
- 无效组织、用户 ID、分组 ID、平台或状态参数返回明确的 400，不按全部范围执行。
- 没有匹配的生效订阅返回成功和 `reset_count: 0`，前端显示零匹配提示。
- 请求失败后不清空筛选、不关闭确认框，允许用户复核范围或重试。

## 代码边界

| 层级 | 预期职责 |
| --- | --- |
| 前端页面 | 增加组织筛选、批量按钮、筛选快照、确认和结果反馈。 |
| 前端 API/i18n | 扩展列表参数、新增批量重置调用及中英文文案。 |

| 后端 repository | 在分页前执行组织过滤与每日剩余比例稳定排序；原子批量清零符合条件的日用量并返回失效键。 |
| 权限 | 将批量重置路由加入订阅子管理员写操作白名单。 |
| 文档 | 更新 `llm-wiki/wiki/backend.md`、`frontend.md`、`data-and-domain.md`、`security-and-reliability.md` 及 `frontend/src/components/admin/README.md`。 |

不新增数据库字段或 migration，不改变组织用量报表，不改变单条“重置配额”和“重置日限”的现有语义，不把组织名称持久化到用户或订阅表。

## 测试与验收

按 TDD 先写失败测试，再做最小实现：

| 范围 | 必须覆盖 |
| --- | --- |
| Repository | 组织域名精确且忽略大小写；子域名不匹配；跨页前按剩余比例排序；负剩余钳制为 0；无限额置后；相同比例按次排序和 ID 稳定。 |
| Service | 批量范围强制限定生效且未过期订阅；只重置日限；返回准确计数；受影响缓存键全部失效。 |
| Handler/权限 | 参数校验、响应合同、幂等重放、完整管理员与订阅子管理员可用、其他子管理员拒绝。 |
| Frontend API/View | 组织值和最后已应用筛选正确传递；按钮位置和权限正确；确认时冻结筛选快照；重复点击受控；成功、零匹配和失败反馈正确。 |
| 回归 | 单条重置日限仍只传 `daily=true`；单条重置配额仍重置日/周/月；现有分页和表头次排序参数保留。 |
