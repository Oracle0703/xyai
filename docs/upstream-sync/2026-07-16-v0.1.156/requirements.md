# sub2api v0.1.156 上游同步需求

## 目标

基于本地 `main` 新建功能分支，将 `Wei-Shaw/sub2api` 的 `v0.1.156` 固定边界从其 `main` 历史合入，解决冲突并在提交前完成文档、测试和人工可审查证据。

## 背景与操作者

仓库维护者需要持续吸收 `Wei-Shaw/sub2api` 上游版本，同时保留 `docs/features/` 已沉淀的本地业务能力。本次交付的直接操作者和审核者是仓库维护者；Codex 负责固定边界合并、冲突判断、验证与提交前证据组装，不负责未经审核的 commit、push 或部署。

## 约束

- 分支名遵循 `feature/hy/10xxx_XXX`，使用 `feature/hy/10157_同步sub2api主线`。
- 合并采用 `git merge --no-commit --no-ff d515c3045...`，保留双父拓扑但停在提交前。
- 冲突不能整仓接受 ours/theirs；必须依据 merge-base、两侧调用链、测试和上游替代关系逐项判断。
- `docs/features/sub2api -merage-list.md` 只能追加，不得覆盖既有记录。
- wiki 使用 LF，不写入密钥、token 或本机凭据。

## 假设

- 用户所说的“features 文件”对应仓库 `docs/features/` 中沉淀的本地功能及其关联实现，而不是要求无条件保留每一行本地代码。
- `v0.1.156` 标签固定发布代码边界；上游 `main` 的直接子提交 `d515c3045` 仅把 `VERSION` 同步为 `0.1.156`，因此将该提交作为本次 main 合并的最终边界。
